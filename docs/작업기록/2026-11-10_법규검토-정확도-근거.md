# 2026-11-10 개발사업 스마트 법규 검토: 결과 정확도·근거 강화 (1단계)

## 요청
"개발사업 스마트 법규 검토를 업데이트·수정하고 싶다" -> 우선순위 1번 "결과의 정확도·근거"부터 진행(이후 검토 범위 추가, 결과 화면·보고서, 입력 화면).

## 현재 상태 점검 (운영 서버, 샘플: 남해읍 도시계획도로 개설, 토목공사, 필지 2개)
- 연동은 모두 정상: 브이월드 필지·지역지구 조회(주소 3개 성공), 법제처 법령 검색(약 3만 자, 17초), Gemini, 전체 분석 159초(인허가 5건·단계별 28건).
- 결과 내용 문제(제 판단, 사용자 확인 필요): 토목인데 건축법 착공신고, 관련 없는 "교육시설 안전성평가", 조문은 있으나 내용이 다른 인용(예비준공검사 -> 지침 제99조 기성고, 도로대장 -> 도로법 제27조 행위제한), 편입 필지가 있는데 토지보상 절차 누락. 기존 검증은 조문 존재 여부(로컬 62개 법령)만 봤다.

## 원인 (측정으로 확인)
1. **룰 엔진 결함**: `SafeDict`가 모르는 변수를 `False`(= 0)로 읽었다. `False <= 4`는 참이라 `distance_to_school_m <= 4`(교육시설), `not is_park_management_authority_project`(공원사업 시행), `days_until_completion_date <= 60`(예비준공검사)이 변수 없이도 참. 최소 입력(예산·면적)만으로 지식 기반 130개 중 8개가 매칭됐고 그중 3개가 이 결함이었다.
2. **농지 오판**: `'전' in 지역지구` 글자 포함 검사라 "준보전산지"가 농지로 판단됨(샘플 지역지구에서 참 확인).
3. **지역지구 오류 유입**: 브라우저의 브이월드 호출이 실패해도 필지가 "검증 완료"로 처리되고 "VWorld API 도메인 인증 오류…" 문구가 지역지구로 AI에 전달됨. 서버도 "API 에러: …" 문구를 걸러내지 않음.
4. **AI가 룰 엔진 필수 목록을 무시**: 프롬프트에 "반드시 포함"이라 적었지만 결과에는 지키지 않아도 알 수 없었다(수정 후 측정에서 한 샘플의 룰 항목 21개가 AI 결과에 없었음).
5. **인용 검증 범위**: 조문이 존재하는지만 확인, 내용 일치는 확인하지 않음.

- 의심 항목 자동 삭제: 맞는 인용을 지우는 피해가 더 크다(기존 `_verify_citation` 주석과 같은 판단).

- 룰 보완 항목 수가 많을 수 있다(샘플 B 21개): 지식 기반 조건이 AI 추출 변수에 의존해 사업과 관련이 약한 항목이 섞인다. 항목마다 해당 조건을 표시한다. 지식 기반의 조건 정비가 필요하면 별도 작업.

## 후속: 인용 판정을 세 단계로 엄격하게 (2026-11-10)
운영 확인에서 기존 판정기가 제목이 어긋난 인용을 놓쳤다(한 실행에서 내용 불일치 의심 0건, 제가 조문 제목과 항목을 대조해 보면 부적합 5건: 착공신고 -> 건설산업기본법 제41조(시공자의 제한), 건설공사대장 전자통보 -> 제22조(도급계약의 원칙), 공사기간 적정성 검토 -> 시행규칙 제3조(심의대상이 아닌 공사), 시설물 인수인계 -> 지방계약법 제17조(검사), 도로시설물 관리대장 -> 도로법 제23조(도로관리청)).
- **원인**: `citation_check._judge`는 Q&A 답변용으로 "주제가 명백히 다른 분야일 때만" 의심하도록 일부러 느슨하게 만든 판정기다(오탐이 답변 신뢰를 깎는다는 측정 때문). 법규 검토 보고서에는 맞지 않았다.
- **변경**: `law_review_verify.strict_judge` 신설(fit / weak / off). weak는 새 상태 "확인 필요"(가벼운 표시), off는 "내용 불일치 의심". 집계: 인용 조문 중 하나라도 fit이면 일치, 전부 off면 불일치 의심, 그 외는 확인 필요. 판정이 실패·미상이면 일치. 보고서에 "? 확인 필요" 배지·요약. 시험 26개(세 단계 집계, 구 판정기 호환, AI 호출 해석·실패, 기본 판정기).
- **측정**(저장해 둔 결과 3건, 항목 96개, 새 AI 분석 없이 판정만 다시; 판정 결과는 실행마다 조금 달라질 수 있다): 제가 틀리다고 본 9건(운영 샘플 5 + 로컬 샘플 4) 중 기존 판정기 4건, 엄격 판정기 **9건 전부** 표시. 표시된 항목은 조문 없음 6건을 빼고 16건(약 18%)이고, 그중 맞는 인용을 표시한 것으로 보이는 것은 약 7건(환경관리비 사용계획 3건, 경관심의, 설계안전성검토(DFS), 시설물 인수인계(기부채납), 소규모 재해영향평가)이다. 첫 프롬프트에서는 제목이 항목과 거의 같은 "우수유출저감대책 수립"·"품질시험계획 수립"까지 의심해 "제목이 항목 이름과 사실상 같으면 fit" 지시를 추가했고(오탐 2건 감소), 대신 "지적확정측량 -> 도시개발사업 특례 조문"(도로 사업에는 맞지 않는 인용으로 보임)이 일치로 넘어갔다.
- **한계**: 정답 표시는 제 판단(조문 제목 대조)이라 실무자 확인이 필요하다. "확인 필요"에는 맞는 인용이 섞이며, 가벼운 표시로만 쓴다. 표본이 3건이다.


## 후속 2: 운영에서 판정이 조용히 실패한 정황, 실패를 숨기지 않게 (2026-11-10)
엄격 판정 배포 후 운영에서 같은 샘플을 두 번 돌렸다.
- 1회차: 177초 만에 "AI가 반환한 데이터를 파싱할 수 없습니다"로 끝남(주 AI 응답이 JSON이 아니었음).
- 2회차: 134초 완료, 항목 36개. 그런데 확인 필요 0건·불일치 의심 0건(삭제된 조문 1건만). **같은 결과에 판정만 로컬에서 다시 적용하니 확인 필요 3건(지적확정측량, 설계안전성검토 DFS, 도로시설물 유지관리 -> 도로법 제40조 접도구역) + 불일치 의심 1건(주민 의견 청취 -> 국토계획법 제89조 이행 담보)이 나왔다.** 즉 운영의 AI 판정 호출이 실패해 항목이 판정 없이 "원문 확인"으로 남았을 가능성이 크다. 지금까지는 실패해도 아무 표시가 없어 알 수 없었다(앞서 "내용 불일치 의심 0건"이 판정기가 느슨해서였는지 실패해서였는지도 확정할 수 없게 됨).
- 운영 로그에 접근할 수 없어 실패 사유는 아직 모른다(후보: 호출 한도, 시간 초과, 모델 설정). 그래서 원인을 추정해 고치지 않고 **실패를 보이게** 했다.
- 변경: `strict_judge`는 일시 오류를 한 번 다시 시도하고 그래도 실패하면 예외를 올린다. `verify_citations`가 실패 사유를 모아 `postprocess`가 보고서 경고로 남긴다(원문 확인은 내용이 맞다는 뜻이 아님). 주 AI 응답 해석(`parse_law_review_json`): 코드 블록·앞뒤 설명 글을 걷어 내고, 해석 실패 시 한 번 더 생성. 시험 30개(재시도, 일시 오류 복구, 실패 기록·경고, 해석 함수).
- 다음: 배포 후 운영에서 다시 돌려 경고가 뜨면 그 사유로 원인을 잡는다. 경고 없이 항목이 표시되면 정상이다.


## 후속 3: 운영 장애 - 재배포 후 JSON 모드 AI 호출 전부 실패 (2026-11-10)
- 증상: 판정 실패 경고를 배포한 뒤 운영에서 다시 돌리자 경고에 사유가 나왔다 - `400 INVALID_ARGUMENT: JSON mode is not enabled for api version v1. Use api version v1beta instead.` 판정 호출 5번이 모두 같은 오류.
- 영향 범위 확인: 운영에서 법정 의무 마스터 API(`/api/search_duties_chunk`)를 직접 호출하니 같은 오류로 실패(0.3~1.6초 만에). **법정 의무 마스터와 PQ 서류 추출, 법규 검토 인용 판정(그리고 Q&A 인용 주제 판정)이 모두 같은 이유로 깨져 있었다.** 11월 1일 운영 확인 때는 정상이었다.
- 원인(추정, 운영 로그·설치 버전은 볼 수 없음): `requirements.txt`의 `google-genai`가 버전 고정이 없어 재배포 때 최신이 설치되고, 그 버전(또는 환경)이 기본 API 버전을 v1으로 써서 `response_mime_type`(JSON 모드)을 거부했다. 로컬은 google-genai 2.12.1(v1beta 기본)이라 시험에서 드러나지 않았다.
- 변경: `gemini_client.get_client()`가 `HttpOptions(api_version="v1beta")`를 직접 지정(환경변수 `GEMINI_API_VERSION`으로 덮어쓸 수 있음), 시작 시 SDK 버전·API 버전을 로그로 남김. 시험 `test_gemini_version.py`(버전 고정, 클라이언트 공유, 실제 SDK가 인자를 받음) + 일일 의존성 점검 목록에 추가. 실제 키로 로컬 JSON 모드 호출 성공 확인.
- 교훈: 의존성이 고정되지 않으면 재배포가 곧 업그레이드다. 앞서 법규 검토 인용 판정이 "조용히 실패"해서 이 장애를 늦게 발견했다 - 판정 실패를 보이게 한 변경이 바로 이 장애를 드러냈다.
- 권장(미실시): `google-genai`를 검증한 버전으로 고정하는 것을 검토(다른 패키지와 충돌하면 배포가 실패할 수 있어 이번에는 하지 않음).
