# 2026-11-27 Codex 교차 검토 도입과 첫 검토 결과

## 도입
- 구현은 Claude Code 만 하고, Codex(OpenAI)는 **읽기 전용 검토 전용**으로 연결했다. 이 컴퓨터에 Node.js 26.13.1, `@openai/codex` 0.172.0 설치, ChatGPT 계정 로그인. 공통 규칙은 `AGENTS.md`(backend, 루트), `CLAUDE.md`가 `@AGENTS.md`로 가져온다.
- 검토를 받는 기준과 절차는 `CLAUDE.md`의 "코드 검토에 Codex 쓰기" 절 참고(계산·판정, AI 호출 방식, 보안·개인정보, 배포·저장 방식, 큰 구조 변경 / 사용자 동의 필수 / 지적은 직접 확인 후 보고).

## 실행에서 알게 된 것
- Windows 에서 `codex exec --sandbox read-only` 는 **작업 폴더의 파일·git 을 읽는 명령이 막혀** 코덱스가 검토를 못 했다(자기 말로 "근거 없이 지적을 꾸며내지 않겠다"며 거절).
  -> 검토할 코드(diff, 파일 전체, 시험)를 **요청문에 직접 넣고** 빈 폴더에서 실행했다(약 59KB).
- 긴 한국어 요청문을 명령 인자로 주면 PowerShell/npm 래퍼가 단어로 쪼개 오류(`unexpected argument`)가 난다 -> `cmd /c "codex exec ... - < 요청문.txt"`로 파일 입력을 쓴다.
- 코드를 외부로 보내기 전 보호: 추적 파일만 담은 임시 worktree 사용(.env·가상환경 없음), 내장 키(`_V`, `_L`) 가림, 키 모양 문자열 검색 0건, 요청문에도 키 검색 0건.
- `AGENTS.md`를 코덱스가 읽는지는 이 방식에서 확인하지 못했다(저장소를 못 읽으므로).

## 검토 대상과 결과 (Gemini 모델 교체 9e533d7, AI 오류 구분 dfb1bee)
코덱스 지적 9건을 **하나씩 코드로 확인**해 판정했다.
| 지적 | 판정 | 조치 |
|---|---|---|
| 크레딧 소진 판별이 문구에만 의존, 402 코드는 안 봄(문구가 바뀌면 `rate`로 분류돼 다른 모델을 계속 부름) | **맞음**(코덱스는 `other`라 했지만 실제로는 `rate`) | `code == 402` 면 크레딧 소진. 429 에 섞인 "billing depleted" 는 크레딧으로 보지 않음 |
| 분류 못 한 오류의 원문 150자가 화면에 노출 | **맞음** | 화면에는 오류 종류만, 원문은 `cause`·서버 로그에만 |
| 400 재시도가 설정 때문이 아닌 400 에도 적용, 원인 은폐·이중 과금 가능성 | **부분적으로 맞음** | 재시도는 최대 1회이고 400 은 요청이 처리되지 않은 오류라 이중 과금 근거는 없음. 키워드로 제한하면 실측한 lite 의 `thinking_budget=0` 400(메시지가 "invalid argument"뿐)을 놓치므로 유지. 재시도도 실패하면 `bad_request` 로 올라가는 시험 추가 |
| 환경변수 모델 목록 정규화 누락으로 중복 호출 | **절반 맞음** | `main_fallbacks()`는 이미 접두사를 정리하지만 호출자가 넘기는 목록은 아니었음 -> 접두사·공백 정리 후 중복 제거 |
| 단일 모델 목록에도 예비 모델 추가 | **설계 의도** | 마지막 예비로 일부러 추가. 문서에 이유가 있고 시험이 확인 |
| `lite` 문자열로 minimal 지원 판정 | 추측(실측 두 모델 기준 정확) | 보류. 새 모델이 나오면 실측 후 표로 바꿀 것 |
| 음수·문자열 예산 | 음수는 **맞음**(2.x 의 -1 은 동적 사고인데 3세대에서 low/minimal 로 바뀜), 문자열은 내부 호출이 항상 정수라 해당 없음 | 3세대에서 음수는 모델 기본값으로 |
| 보조 단계 예외 시 스레드 풀 정리 누락 | **맞음** | 두 풀 모두 예외 경로에서 `shutdown(wait=False)` + 시험 |
| 빈 `models` 목록이 기본 모델을 호출 | 참고(해당 호출 없음) | 변경 없음 |
- 추가: 실제 API 에서 없는 모델을 부르면 404 가 와서 `other` 로 나오는 것을 확인 -> 모델 폐기 상황에 유용하도록 `model` 종류와 전용 안내를 추가.
- 실제 API 로 `gemini-3.8-flash`/`gemini-3.5-flash-lite` 호출(사고 0, temperature, `models/` 접두사, 음수 예산) 정상 확인.
