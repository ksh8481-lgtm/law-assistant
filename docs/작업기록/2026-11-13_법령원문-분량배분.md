# 2026-11-13 기타 행정 검토: "법령 원문이 없으니 직접 찾아보라" 문제

## 문제
사용자가 보낸 검토 결과 PDF(관광단지 면적 변경 시 재해영향평가를 받아야 하는지)에 "(중요) 현재 제공된 법령 데이터베이스에는 자연재해대책법 원문이 포함되어 있지 않습니다 ... 법제처에서 직접 참조하시기 바랍니다"라고 나왔다. 재해영향평가의 핵심 법령인데 왜 원문이 없는가?

## 원인(재현으로 확인)
- 같은 질문을 로컬에서 돌려 `_extract_keyword_and_jurisdiction`을 보니 AI는 **자연재해대책법을 올바르게 뽑았다**: [재난 및 안전관리 기본법, 관광진흥법, 자연재해대책법].
- 그런데 컨텍스트에 실린 법령 발췌는 재난안전기본법(법 6,144 + 시행령 8,404 + 시행규칙 1,371자)과 관광진흥법(5,841자)뿐이었다. `search_laws_with_text`가 총 분량 상한 20,000자를 **이름 순서대로 앞에서부터** 쓰고 `if total_len >= max_total_len: break`로 나머지 이름을 건너뛰기 때문에, 앞의 두 법령이 상한을 채우면 세 번째 이름은 **조용히** 빠진다. 빠졌다는 표시도 없어서 AI는 "원문이 없다"고 보고 사용자에게 직접 찾아보라고 했다.
- 자연재해대책법만 따로 조회하면 정상으로 조문 제4조·제5조·제5조의2와 시행령 제6조·별표 1이 나온다(검색 문제는 아님).

## 변경
`moleg_mcp.search_laws_with_text`를 2단계로: (1) 모든 이름의 본 법률을 상한과 무관하게 먼저 싣는다 (2) 시행령은 모든 법령에 대해, 시행규칙은 그다음에, 각각 본 법률 발췌에 질의 핵심어가 많은 법령부터 상한까지 채운다. 못 실은 법령·이름을 못 찾은 법령은 프롬프트에 목록으로 적는다. 첫 질의 경로 상한 20,000 -> 34,000자.

## 측정(같은 질문, 로컬 실제 AI)
| | 싣린 법령 발췌 | 답변 |
|---|---|---|
| 수정 전 | 재난안전기본법 3단, 관광진흥법 (자연재해대책법 없음) - 컨텍스트 23,476자 | 자연재해대책법 원문이 DB에 없다, 직접 확인하라 |
| 본 법률 보장만(상한 20,000자) | 본 법률 3개 + 자연재해대책법 시행령(별표 1 포함) - 31,183자 | 자연재해대책법 제4조·제5조 제1항 제8호("관광단지 개발") 인용, 그러나 "관광진흥법 시행령 원문이 없으니 직접 확인" |
| 본 법률 보장 + 상한 34,000 + 시행령 먼저 | 본 법률 3 + 관광진흥법 시행령(제44조 경미한 면적 변경) + 자연재해대책법 시행령 - 39,440자 | 두 법령의 조문으로 결론, 직접 확인 안내 없음(83초) |
- 두 번째 시도에서 한 번 더 발견: 법령별로 시행령·시행규칙을 몰아서 채웠더니 자연재해대책법 시행규칙(7,900자)이 관광진흥법 시행령보다 먼저 상한을 써서 관광진흥법 시행령이 빠졌다 -> 시행령을 전 법령에 먼저 채우도록 순서를 바꿨다.
- 답변의 인용 점검(`citation_check`)도 정상 동작: 모델이 기억으로 쓴 "30%"가 시행령 제44조 원문에 없다고 💡로 표시했다.

## 기각
- 상한만 키우기: 법령이 몇 개 걸리든 앞 법령이 먼저 쓰면 같은 문제가 다시 생긴다(근본 원인은 앞에서부터 쓰는 배분).
- AI가 법령 이름을 중요도 순으로 정렬하게 하기: 순서는 비결정적이라 의존할 수 없다(이번에도 핵심 법령이 맨 뒤였다).
- 모든 법령의 시행령·시행규칙을 무제한으로: 프롬프트가 크게 늘고 답변이 느려진다(3개 법령이면 70,000자 이상).

## 한계
- 상한 안에서 시행규칙은 여전히 빠질 수 있다(빠지면 목록으로 알린다). 이름 5개까지 모두 본 법률이 실리므로 최악 프롬프트는 본 법률 25,000자 + 추가분이다.
- 핵심어 빈도로 법령 관련도를 가늠하므로 드물게 덜 중요한 법령의 시행령이 먼저 들어갈 수 있다.
- 이 수정은 "원문을 못 실은" 경우를 줄이고 알리는 것이다. AI가 법령명 자체를 못 뽑은 경우(키워드·법령명 추출 단계)는 별개 문제다.

## 되돌리기
`moleg_mcp.search_laws_with_text`의 이전 구현(이름 순서대로 앞에서부터 채움)과 `mcp_agent_sync`의 `max_total_len=34000` 인자를 되돌리면 된다.
