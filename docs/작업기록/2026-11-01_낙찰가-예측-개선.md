# 2026-11-01 낙찰가 예측 개선 (투찰 추천 모델)

## 요청
"낙찰가 예측 항목에서 예전 입찰 데이터를 분석해서 새로운 공사 입찰에 입찰가격으로 활용하려고 한 것. 좀 더 잘 낙찰될 수 있게 업데이트." (처음에는 직전에 만든 적격심사 계산과 합치는 것으로 오해했다 - 낙찰가 예측 자체의 개선이었다.)

## 현재 방식의 문제 (실제 나라장터 공사 낙찰 데이터로 확인: "도로" 공고 1,885건, 최근 6개월)
1. 낙찰률(낙찰금액÷예정가격)이 아주 좁게 몰린다(하위 10%~상위 10% = 90.01%~91.04%). 0.1%p 차이로 탈락하거나 진다.
2. 투찰 때는 예정가격을 모르고 기초금액만 안다. 예전에는 "기초금액 × 낙찰률 ± 3%"로 환산했는데, 실제 공고 25건의 사정률(예정가격÷기초금액)은 98.5~101.1%로 ±3%보다 훨씬 좁았고, 소액 공사에서는 ±3%가 낙찰 구간(1%p)보다 컸다.
3. **백테스트가 틀렸다**: "추천 낙찰률이 실제 낙찰률보다 낮거나 같으면 이긴다"고만 봐서, 낮게 쓸수록 승률이 높게 나왔다(최소값 83.477% 추천 → 승률 100%, 하위10% → 95%). 낙찰하한 아래는 무조건 탈락인데 반영하지 않았다. 화면의 "추천 목표 입찰가"도 하위 10%였다.
4. 참가업체 수·규모 정보를 쓰지 않았다(참가 20~59곳 표준편차 0.60, 60~119곳 0.36).

## 새 방식 (`bid_model.py`, `bid_sampling.py`, `bid_service.py`)
- 과거 공고의 기초금액을 조회(최근순 표본 최대 120건, 메모리 보관)해 사례마다 w=낙찰금액÷기초금액, 사정률, 낙찰하한 f=사정률×낙찰하한율을 구한다. 사정률이 96.5~103.5%를 벗어나는 사례(금액 기준이 다른 경우)는 뺀다.
- 사례 i에서 기초금액의 x%로 썼다면 이긴 조건 = f_i ≤ x < w_i. 이긴 사례의 비율이 낙찰 확률 P(x). 산 모양이라 목표 확률(30~70%)별로 "그 확률 이상인 가장 높은 가격"(이윤 큰 쪽)을 추천하고, 확률 최고 지점·하한가 대비 여유·원 단위 금액을 보여 준다. 과거 사례로 도달할 수 없는 확률은 "도달 불가"로 표시.
- 낙찰하한율은 입력값 우선, 없으면 낙찰률 하위 2% 지점에서 추정(중앙값보다 6%p 넘게 낮은 다른 방식 낙찰은 제외).
- 경쟁 규모(참가업체 수)·공사 규모(기초금액 0.5~2배) 필터와 구간별 표. 사례가 적으면 좁히지 않고 이유를 표시.
- 백테스트 교체: 학습 구간으로 정한 가격을 검증 구간 사례에 대 보고, 학습에서 예상한 확률과 실제를 비교(낮게 쓰기·중앙값은 비교용). 예전 `per_percentile` 표는 응답에서 제거(`pps_bid.backtest_bid_strategy`는 남아 있으나 API에서 쓰지 않음).

## 검증 (실제 데이터)
- 학습 4개월(기초금액 확인 145건) → 검증 2개월(93건): 목표 30% → 실제 34.4%, 50% → 59.1%, 확률 최고(53.1%) → 62.4%. **예상이 약간 보수적**으로 맞는다. 낮게 쓰기(하위 10%)는 예상 36.6% → 실제 45.2%로 확률 최고 지점보다 낮다(예전 방식이 권하던 쪽이 불리함을 확인).
- 화면(기초금액 157,981,000원, 키워드 도로, 6개월): 투찰 추천 40.4%(90.198%, 142,496,334원), 17초. 백테스트: 목표 30%→31.3%, 40%→42.2%(예상 30.0·41.0%), 16초.
- 시험 `test_bid_model.py` 19개(사례 계산, 하한 반영, 목표 확률별 추천, 필터·구간, 백테스트가 낮게 쓰기를 더 낫게 보지 않음, 표본 조회 캐시·없음/일시 오류 구분, API).

## 한계
- 한 가격으로 낙찰되는 비율은 보통 40~60%를 넘지 못한다(사정률 98~101% 변동 때문). 낙찰을 보장하지 않으며 화면에도 표시한다.
- 낙찰하한율을 추정하는 경우 공고문 값과 다를 수 있다(입력 권장). 공사 데이터만 쓴다.
- 기초금액을 사례마다 조회하므로 공공데이터 일일 호출 한도를 쓴다(캐시로 줄임). 서버 재시작 시 캐시가 사라진다.
