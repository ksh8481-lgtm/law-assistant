# 2026-11-01 낙찰가 예측 개선 (투찰 추천 모델)

## 요청
"낙찰가 예측 항목에서 예전 입찰 데이터를 분석해서 새로운 공사 입찰에 입찰가격으로 활용하려고 한 것. 좀 더 잘 낙찰될 수 있게 업데이트." (처음에는 직전에 만든 적격심사 계산과 합치는 것으로 오해했다 - 낙찰가 예측 자체의 개선이었다.)

## 현재 방식의 문제 (실제 나라장터 공사 낙찰 데이터로 확인: "도로" 공고 1,885건, 최근 6개월)
1. 낙찰률(낙찰금액÷예정가격)이 아주 좁게 몰린다(하위 10%~상위 10% = 90.01%~91.04%). 0.1%p 차이로 탈락하거나 진다.
2. 투찰 때는 예정가격을 모르고 기초금액만 안다. 예전에는 "기초금액 × 낙찰률 ± 3%"로 환산했는데, 실제 공고 25건의 사정률(예정가격÷기초금액)은 98.5~101.1%로 ±3%보다 훨씬 좁았고, 소액 공사에서는 ±3%가 낙찰 구간(1%p)보다 컸다.
3. **백테스트가 틀렸다**: "추천 낙찰률이 실제 낙찰률보다 낮거나 같으면 이긴다"고만 봐서, 낮게 쓸수록 승률이 높게 나왔다(최소값 83.477% 추천 → 승률 100%, 하위10% → 95%). 낙찰하한 아래는 무조건 탈락인데 반영하지 않았다. 화면의 "추천 목표 입찰가"도 하위 10%였다.
4. 참가업체 수·규모 정보를 쓰지 않았다(참가 20~59곳 표준편차 0.60, 60~119곳 0.36).

## 새 방식 (`bid_model.py`, `bid_sampling.py`, `bid_service.py`)
- 과거 공고의 기초금액을 조회(최근순 표본 최대 120건, 메모리 보관)해 사례마다 w=낙찰금액÷기초금액, 사정률, 낙찰하한 f=사정률×낙찰하한율을 구한다. 사정률이 96.5~103.5%를 벗어나는 사례(금액 기준이 다른 경우)는 뺀다.
- 사례 i에서 기초금액의 x%로 썼다면 이긴 조건 = f_i ≤ x < w_i. 이긴 사례의 비율이 낙찰 확률 P(x). 산 모양이라 목표 확률(30~70%)별로 "그 확률 이상인 가장 높은 가격"(이윤 큰 쪽)을 추천하고, 확률 최고 지점·하한가 대비 여유·원 단위 금액을 보여 준다. 과거 사례로 도달할 수 없는 확률은 "도달 불가"로 표시.
- 낙찰하한율은 입력값 우선, 없으면 낙찰률 하위 2% 지점에서 추정(중앙값보다 6%p 넘게 낮은 다른 방식 낙찰은 제외).
- 경쟁 규모(참가업체 수)·공사 규모(기초금액 0.5~2배) 필터와 구간별 표. 사례가 적으면 좁히지 않고 이유를 표시.
- 백테스트 교체: 학습 구간으로 정한 가격을 검증 구간 사례에 대 보고, 학습에서 예상한 확률과 실제를 비교(낮게 쓰기·중앙값은 비교용). 예전 `per_percentile` 표는 응답에서 제거(`pps_bid.backtest_bid_strategy`는 남아 있으나 API에서 쓰지 않음).

## 검증 (실제 데이터)
- 학습 4개월(기초금액 확인 145건) → 검증 2개월(93건): 목표 30% → 실제 34.4%, 50% → 59.1%, 확률 최고(53.1%) → 62.4%. **예상이 약간 보수적**으로 맞는다. 낮게 쓰기(하위 10%)는 예상 36.6% → 실제 45.2%로 확률 최고 지점보다 낮다(예전 방식이 권하던 쪽이 불리함을 확인).
- 화면(기초금액 157,981,000원, 키워드 도로, 6개월): 투찰 추천 40.4%(90.198%, 142,496,334원), 17초. 백테스트: 목표 30%→31.3%, 40%→42.2%(예상 30.0·41.0%), 16초.
- 시험 `test_bid_model.py` 19개(사례 계산, 하한 반영, 목표 확률별 추천, 필터·구간, 백테스트가 낮게 쓰기를 더 낫게 보지 않음, 표본 조회 캐시·없음/일시 오류 구분, API).

## 한계
- 한 가격으로 낙찰되는 비율은 보통 40~60%를 넘지 못한다(사정률 98~101% 변동 때문). 낙찰을 보장하지 않으며 화면에도 표시한다.
- 낙찰하한율을 추정하는 경우 공고문 값과 다를 수 있다(입력 권장). 공사 데이터만 쓴다.
- 기초금액을 사례마다 조회하므로 공공데이터 일일 호출 한도를 쓴다(캐시로 줄임). 서버 재시작 시 캐시가 사라진다.

## 정정 (같은 날 후속 작업: 낙찰하한을 추정이 아니라 예규 값으로)
사용자 지적: "300억 미만 공사는 낙찰하한율이 정해져 있잖아?" → 맞다. 위 첫 버전은 낙찰하한율을 낙찰률 분포에서 **추정**했고, 그 때문에 결과가 크게 부풀었다.

- **무엇이 틀렸나**: 하한을 낙찰률 하위 2% 지점(예정가격 대비 약 90.0%)으로 잡았지만, 실제 하한은 (입찰가격−A)÷(예정가격−A) ≥ 89.745% 이고 A(보험료·안전관리비 등 약 5.8%)가 있어 예정가격 대비로는 약 90.3%였다. 이 0.3%p 차이가 낙찰자가 몰린 구간(1%p 안팎) 안이어서, "40% 안팎으로 낙찰된다"던 확률은 **과장**이었다. 위 '검증'과 '한계'의 40~60% 수치는 취소한다.
- **규정 값**: [별표 1]~[별표 7] 입찰가격 식과 적격통과점수에서 구간별 하한을 계산(`bid_rules.py`, `award_specs/jibang_gongsa_floor.json`): 2~10억 89.745%, 10~50억 88.745%, 50~100억 87.495%, 100~300억 81.995%(가격 외 점수 만점 기준). 새 예규 PDF에서 값 33개를 자동 대조한다(`award_check.py`, 현행 PDF와 모두 일치). 이 과정에서 [별표 1]의 고정점수(98% 이상 22점)가 명세에서 빠져 있던 것도 바로잡았다(하한에는 영향 없음).
- **실제 데이터 재측정**(키워드 도로, 6개월, 기초금액 157,981,000원, A 9,113,864원, 사례 113건): 확률 최고 지점 약 6.0%(143,301,919원), 하한가 142,617,628원(범위 141.1M~143.8M, 사정률 하위10~상위10%). 백테스트(학습 49·검증 60건): 확률 최고 예상 8.2% → 실제 1.7%, 중앙값 방식 4.1% → 5.0%, 낮게 쓰기 8.2% → 3.3%. 목표 30~70%는 과거 사례로 도달 불가.
- **해석**: 낙찰자는 하한 바로 위(+0.05~0.15%p)에 몰려 있는데 사정률이 개찰 때 ±0.5% 정도(기초금액의 약 ±0.8M원) 흔들려 한 가격으로는 한 자릿수%밖에 못 잡는다. 화면은 이를 숨기지 않고 낙찰 / 하한 미달 / 더 낮은 가격 패배 세 갈래와 "도달 불가"로 보여 준다.
- **추가한 입력**: A값(공고 선택 시 자동), 내 가격 외 점수(비우면 만점). 낙찰하한율 입력은 없앴다(규정에서 계산).
- **한계 확인**: 이 작업 중 공공데이터 기초금액 API 일일 호출 한도(429)에 걸려 마지막 화면 점검은 기초금액만 가짜로 대체한 로컬 서버로 했다(낙찰 이력은 실제 API). 운영 키도 같은 한도를 쓴다.

## 후속 (2026-11-03): 분석 시 기초금액 누락 방지
사용자 지적: "제대로 된 분석이 되려면 분석 시 정보가 누락되면 안 되는데." 운영 확인에서 기초금액 조회 120건 중 65건이 시간 초과로 빠진 채(사례 54건) 결과가 나왔고, 같은 조건을 다시 누르면 숫자가 달라졌다(최고 확률 7.4% → 5.8%).

- **원인**: 동기 요청이 게이트웨이 60초 안에 끝나야 해서 기초금액 조회 시간을 25초로 제한했고, 운영 서버의 조회 속도(초당 약 1.5건)로는 120건을 못 채웠다. 못 가져온 사례는 조용히 빠졌다.
- **변경**: ① 분석·백테스트를 백그라운드 작업(`/start` + `/api/analyze/bid_job/<id>`)으로 바꿔 최대 200초 동안 끝까지 조회, 진행률 표시. ② 시간 초과·일시 오류는 여러 번 다시 시도(3번 연속 한 건도 못 얻으면 중단). ③ 호출 한도 초과는 게이트웨이 응답(`cmmMsgHeader`)에서 읽어 구분하고 즉시 멈춤(예전에는 모두 "알 수 없는 오류"). ④ 기초금액·A값을 디스크(`bid_base_cache.json`)에도 보관해 재시작 후에도 유지. ⑤ 끝까지 못 가져온 사례가 있으면 결과 상단에 "불완전한 결과" 경고와 사유(한도 초과/응답 없음)를 표시하고, 월별 낙찰 이력 조회 실패도 요약에 표시.

- **한계**: 한도 초과 시에는 어떤 방법으로도 못 가져온다(경고만). 컨테이너 디스크가 재배포 때 초기화되면 보관 값도 사라진다.

## 타당성 조사 (2026-11-03): 사정률(예정가격÷기초금액)을 더 잘 맞힐 수 있나 -> 없다
낙찰 확률의 거의 전부가 예정가격(사정률)에 달려 있다(사정률을 정확히 알면 최고 낙찰 확률 95.8%, 중앙값으로 가정하면 4.9%). 그래서 발주기관·시기·규모로 사정률을 예측할 수 있는지 실제 데이터로 확인했다.

- **표본**: 도로 공고 12개월 5,825건 중 건수가 많은 발주기관 12곳의 최근 25건씩, 기초금액을 조회해 288건(기초금액 조회 300건 사용, 실패 0).
- **분포**: 평균 99.82%, 중앙값 99.82%, 표준편차 0.77%p, 왜도 -0.01, 하위5~상위5% = 98.53~101.08%. 좌우 대칭의 종 모양.
- **발주기관**: 기관 차이가 분산의 2.5%만 설명(F=0.63, 유의 기준 약 1.8 미만). 기관별 평균은 99.56~99.97%로 사실상 같다. 하나 빼고 예측 오차(RMSE): 전체 평균 0.770 / 기관 평균 0.791 / 기관 평균(축소) 0.782 -> 기관 정보를 쓰면 오히려 나빠진다.
- **시간 순서**: 개찰일 순 인접 사례 상관 -0.013, 같은 기관 안 직전 사례와의 상관 0.008 -> 직전 결과가 다음을 알려 주지 않는다.
- **다른 변수**: log 기초금액 0.013, 참가업체 수 0.023, A/기초금액 -0.060, 개찰 월 0.012, 요일 -0.052 -> 모두 0에 가깝다.
- **무작위 기준선**: 예비가격 15개(기초금액 ±3%)에서 입찰자 150명이 4개씩 골라 가장 많이 선택된 4개의 평균으로 예정가격을 정하는 방식을 모의하면 표준편차 0.87%p(실제 0.77). 실제 분포는 이 추첨의 무작위 분포와 같다.
- **결론**: 사정률은 입찰자들의 추첨으로 정해지는 무작위 값이라 개찰 전에 더 좁힐 방법이 데이터에서 보이지 않는다. 기관·시기·규모로 예측하는 기능은 만들지 않는다(만들면 오히려 오차가 커진다). 한 가격으로 낙찰되는 확률이 한 자릿수%인 것은 모델의 한계가 아니라 이 제도의 성질이다.
- **남는 레버**: (정정, 아래 두 번째 조사 참고) 참가업체 수가 적은 공고를 고르는 것도 낙찰 확률을 의미 있게 올리지 못한다. 여러 공고에 같은 방식으로 입찰해 기대 낙찰 건수를 늘리는 것 정도다.
- 한계: 12개 기관·도로 공고·12개월 표본이다. 다른 공종이나 기관에서 다를 수 있으나 이 표본에서 신호는 전혀 없었다.

## 타당성 조사 2 (2026-11-03): 참가업체 수를 가늠하고 공고를 골라 입찰하면 낙찰 확률이 오르나 -> 거의 안 오른다
앞 조사에서 "참가업체 수가 적은 공고를 고르면 유리할 수 있다"고 적었던 근거는 운영 분석 화면의 구간별 표(20~59곳 12.5%, 60~119곳 11%, 120곳 이상 4%)였다. 이 표는 구간당 9~25건짜리라 우연일 가능성이 컸고, 아래에서 확인해 틀렸음을 바로잡는다.

- **참가업체 수는 어느 정도 예측된다**(도로 공고 12개월 5,813건, 시간 순 앞 70%로 학습·뒤 30%(1,744건)로 검증): 중앙값 75곳, 하위10% 18곳~상위10% 672곳. 로그 기준 R2 = 규모만 0.21, 발주기관 평균만 0.22, 규모+공고명 키워드+기관 유형 0.27, 전부 + 기관 평균 0.36. 구간(1~19/20~59/60~119/120곳 이상) 맞히기: 가장 흔한 구간만 찍으면 38%, 전부 쓰면 정확히 52%·한 구간 이내 91%. 영향이 큰 특징: 전기·가로등 공고(+), 낙찰금액이 클수록(+, 2배 규모당 약 1.4배), 광역·본부급 기관(+), 군 단위 기관(-), 철거·교량(-). 같은 기관의 직전 사례와 참가업체 수 상관 0.50.
- **그런데 낙찰 확률은 거의 안 변한다**(사정률 조사 표본 288건, 최고 낙찰 확률을 참가업체 수 구간별로 계산): 1~59곳 7.5%, 60~119곳 7.1%, 120곳 이상 5.6%. 구간 간 차이가 표본 오차(부트스트랩 구간이 크게 겹침) 안이다. 낙찰자의 비율 분포(하한 위 0.0~0.1%p에 몰림)도 구간과 무관하게 비슷하다(표준편차 0.13~0.24).
- **결론**: 참가업체 수 예측 지표나 "경쟁 적은 공고 고르기" 기능은 만들지 않는다. 예측은 되지만 그 정보가 낙찰 확률을 올리지 못한다(7.5% → 5.6% 수준, 우연과 구분되지 않음). 화면의 "예상 경쟁 규모" 필터는 비슷한 규모의 사례로 계산하려는 용도로만 남긴다. 최고 확률은 학습 표본 안에서 가장 좋은 지점을 고른 값이라 낙관적이고, 백테스트 실제는 1.5~5%였다.
- 정직한 기대치: 소액 공사 한 건의 낙찰 확률은 3~7%, 입찰 100건이면 약 3~7건. 이익이 이 확률과 낙찰 건당 이윤으로 정해진다.
